1. Why Spring Boot?
      → Spring Boot is built on top of Spring Framework
      → Problems in old Java applications:
         - Too much XML configuration
         - Manual dependency management
      → Spring Boot solves this:
         - Auto configuration
         - Embedded server (Tomcat)
         - Easy dependency management
      → Why industry uses Spring Boot:
         - Scalable
         - Microservice friendly
         - Easy integration with DB, Security, Cloud

2. Build Tool
      → Build tool manages project dependencies and build process
      → Common build tools:
         - Maven
         - Gradle
      → Responsibilities:
         - Download libraries
         - Compile code
         - Run tests
         - Build JAR/WAR
      → Gradle:
         - Faster
         - Uses Groovy/Kotlin DSL
         - More flexible
      → Maven:
         - XML based
         - Very common in enterprise

3. Inversion of Control (IoC)
      → Core concept of Spring
      → Traditional Java: Developer creates objects manually
      → Example: UserService service = new UserService();
      → In Spring:
         Spring creates and manages objects
      → Why important:
         - Loose coupling

4. Application Context
      → Spring container
      → Responsibilities:
         - Creates beans
         - Stores beans
         - Injects dependencies
         - Manages lifecycle

5. Beans
      → Object managed by Spring container
      → Bean lifecycle:
         Create → Initialize → Use → Destroy
      → Common annotations:
         - @Component
         - @Service
         - @Repository
         - @Controller
      → Why beans important:
         Spring manages:
         - Object creation
         - Dependencies
         - Scope
         - Lifecycle

6. Dependency Injection (DI)
      → Process of providing dependencies automatically
      → Advantages:
         - Loose coupling
         - Easier testing
         - Better modularity
      → Simple understanding:
         “Object gets dependencies from outside”

7. Types of Dependency Injection
      A. Constructor Injection
      B. Setter Injection
      C. Factory Method

8. Proxies
      → Proxy = wrapper object around original object
      → Spring often does NOT call actual object directly
      → Instead: Spring creates proxy object

      → Proxy intercepts method calls
      → Used for:
         - Transactions
         - Security
         - Logging
         - Lazy loading
         - AOP

      → Example:
         UserService object
         ↓
         Spring creates proxy around it
         ↓
         Proxy adds extra behavior

9. Dynamic Proxy

      → Proxy created at runtime

      → Java provides:
         - JDK Dynamic Proxy
         - CGLIB Proxy

      → Spring uses both internally

   3. Reflection

      → Reflection allows Java to inspect/manipulate classes at runtime

      → Can:
         - Read class metadata
         - Access methods
         - Access fields
         - Create objects dynamically

      → Used heavily in Spring

      → Example:
         Spring scans annotations:
             @Component
             @Autowired

         Using reflection

      → Why important:
         Enables dynamic behavior

   ==================================================

   4. JDK Dynamic Proxy

      → Uses Java Reflection API

      → Works ONLY with interfaces

      Example:
         interface UserService
         ↓
         Spring creates proxy for interface

      → Used when class implements interface

      ❌ Cannot proxy normal classes directly

   ==================================================

   5. CGLIB Proxy

      → Used when no interface exists

      → CGLIB creates subclass dynamically

      Example:
         class UserService
         ↓
         CGLIB creates:
             UserService$$Proxy

      → Works using bytecode generation

      → Spring Boot commonly uses CGLIB

   ==================================================

   6. Why Proxies Important in Spring

      → Core feature behind:
         - @Transactional
         - @Async
         - AOP
         - Security
         - Lazy loading

      → Proxy intercepts method call
      → Adds extra logic before/after method execution

   ==================================================

Spring Advanced:

   8. Spring AOP (Aspect-Oriented Programming)

   1. What is AOP?

      → AOP = Aspect-Oriented Programming

      → Used to separate:
         “Cross-cutting concerns”
         from
         “Business logic”

      → Cross-cutting concerns means:
         Features used in many places

      Examples:
         - Logging
         - Security
         - Transactions
         - Validation
         - Performance monitoring

      → Problem without AOP:
         Same code repeated everywhere

      Example:
         log()
         checkSecurity()
         transactionStart()

         repeated in every method ❌

      → AOP solves this:
         Common logic moved to separate layer

   ==================================================

   2. Simple Real-Life Analogy

      Imagine:
         You enter mall

      Before entering:
         - Security check
         - Ticket validation

      → These happen BEFORE actual shopping

      Same in AOP:
         Extra logic runs:
         - before method
         - after method
         - around method

   ==================================================

   3. Core Idea of AOP

      → Business logic:
         Actual application work

      → Aspect:
         Extra reusable logic

      Example:

         Business Logic:
             transferMoney()

         Aspect:
             logging()
             securityCheck()

      → Spring automatically applies aspect

   ==================================================

   4. Terminologies (VERY IMPORTANT)

      --------------------------------------------------

      A. Aspect

         → Class containing cross-cutting logic

         Example:
             LoggingAspect

         → Contains:
             logging methods
             security methods

      --------------------------------------------------

      B. Join Point

         → Point where extra logic can be applied

         Usually:
             method execution

         Example:
             userService.saveUser()

      --------------------------------------------------

      C. Advice

         → Actual action performed by aspect

         Types:
             - Before
             - After
             - Around
             - AfterReturning
             - AfterThrowing

      --------------------------------------------------

      D. Pointcut

         → Defines WHERE aspect should apply

         → Selects methods/classes

         Example:
             all methods inside service package

      --------------------------------------------------

      E. Weaving

         → Process of connecting aspect with target object

         → Spring does weaving at runtime using proxies

   ==================================================

   5. Types of Advice

      --------------------------------------------------

      A. Before Advice

         → Runs BEFORE method execution

         Example:
             logging before API call

      --------------------------------------------------

      B. After Advice

         → Runs AFTER method execution

      --------------------------------------------------

      C. Around Advice

         → Runs BEFORE and AFTER both

         → Most powerful advice

      --------------------------------------------------

      D. AfterReturning

         → Runs only if method successful

      --------------------------------------------------

      E. AfterThrowing

         → Runs when exception occurs

   ==================================================

   6. Pointcuts (VERY IMPORTANT)

      → Pointcut defines:
         WHERE aspect should apply

      → Example:
         Apply logging only on:
             service layer methods

      → Common syntax:

         execution(* com.app.service.*.*(..))

      Breakdown:
         *                  → any return type
         com.app.service    → package
         *.*(..)            → any class + any method

      → Meaning:
         Apply aspect to all methods in service package

   ==================================================

   7. Practical Usage of AOP

      --------------------------------------------------

      A. Logging

         → Log request and response

         Example:
             API called
             execution time
             parameters

      --------------------------------------------------

      B. Transactions

         → Spring internally uses AOP for:
             @Transactional

      --------------------------------------------------

      C. Security

         → Check authentication before method execution

      --------------------------------------------------

      D. Performance Monitoring

         → Measure execution time

      --------------------------------------------------

      E. Exception Handling

         → Centralized error logging

   ==================================================

   8. How Spring AOP Works Internally

      → Spring creates proxy object

      Flow:

         Client
            ↓
         Proxy Object
            ↓
         Aspect Logic
            ↓
         Actual Method

      → Proxy intercepts method call
      → Executes aspect logic
      👉 Calls actual method

   ==================================================

   9. Example Flow

      Suppose:

         transferMoney()

      Before execution:
         logging()

      During execution:
         transaction management

      After execution:
         success log

      👉 Business logic remains clean

   ==================================================

   10. Advantages of AOP

      → Cleaner code
      → Reusable logic
      → Better separation of concerns
      → Less duplicate code
      → Easier maintenance

   ==================================================

🔥 FINAL UNDERSTANDING

AOP:
   → Adds extra behavior around methods
   → Without changing actual business logic

👉 Simple Flow:
   Request
      ↓
   Proxy intercepts
      ↓
   Aspect executes
      ↓
   Actual method runs

👉 Spring AOP mainly works using:
   - Proxies
   - Reflection
