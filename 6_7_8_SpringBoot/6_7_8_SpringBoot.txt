1. Why Spring Boot?
      → Spring Boot is built on top of Spring Framework
      → Problems in old Java applications:
         - Too much XML configuration
         - Manual dependency management
      → Spring Boot solves this:
         - Auto configuration
         - Embedded server (Tomcat)
         - Easy dependency management
      → Why industry uses Spring Boot:
         - Scalable
         - Microservice friendly
         - Easy integration with DB, Security, Cloud

2. Build Tool
      → Build tool manages project dependencies and build process
      → Common build tools:
         - Maven
         - Gradle
      → Responsibilities:
         - Download libraries
         - Compile code
         - Run tests
         - Build JAR/WAR
      → Gradle:
         - Faster
         - Uses Groovy/Kotlin DSL
         - More flexible
      → Maven:
         - XML based
         - Very common in enterprise

3. Inversion of Control (IoC)
      → Core concept of Spring
      → Traditional Java: Developer creates objects manually
      → Example: UserService service = new UserService();
      → In Spring:
         Spring creates and manages objects
      → Why important:
         - Loose coupling

4. Application Context
      → Spring container
      → Responsibilities:
         - Creates beans
         - Stores beans
         - Injects dependencies
         - Manages lifecycle

5. Beans
      → Object managed by Spring container
      → Bean lifecycle:
         Create → Initialize → Use → Destroy
      → Common annotations:
         - @Component
         - @Service
         - @Repository
         - @Controller
      → Why beans important:
         Spring manages:
         - Object creation
         - Dependencies
         - Scope
         - Lifecycle

6. Dependency Injection (DI)
      → Process of providing dependencies automatically
      → Advantages:
         - Loose coupling
         - Easier testing
         - Better modularity
      → Simple understanding:
         “Object gets dependencies from outside”

7. Types of Dependency Injection
      A. Constructor Injection
      B. Setter Injection
      C. Factory Method

8. Proxies
      → Proxy = wrapper object around original object
      → Spring often does NOT call actual object directly
      → Instead: Spring creates proxy object around original object
      → Proxy act as mediator/interceptor

      → Example: Client ->  Proxy  ->  Server
         - Client send request
         - Proxy checks request
         - Proxy decides:
            → Allow request
            → Block request
            → Add extra processing
        - Then forwards to actual server
      → Example:
         UserService object
         ↓
         Spring creates proxy around it
         ↓
         Proxy adds extra behavior

      → Used for:
         - Transactions
         - Security
         - Logging
         - Lazy loading
         - AOP

9. Dynamic Proxy
      → Proxy created at runtime
      → Java provides:
         - JDK Dynamic Proxy
         - CGLIB Proxy
      → Spring uses both internally

10. Reflection
      → Reflection allows Java to inspect/manipulate classes at runtime
      → Can:
         - Read class metadata
         - Access methods
      → Normal method call: user.introduce()
      → Reflection call:
         Method m = user.getClass().getMethod("introduce", String.class);
         m.invoke(user, "Yash");

      → Method name decided at runtime

      → Relationship Between Reflection and Proxy
         Proxy intercepts method call  →   Reflection invokes actual method
         Example:
            proxy.method()
                  ↓
            invoke()
                  ↓
            method.invoke(realObject, args)

11. Why Spring Boot Startup Time is High?
      → Spring Boot performs many operations during application startup
      → Main reasons:
         - Bean creation
         - Dependency Injection
         - Annotation processing
         - Proxy creation
         - Reflection usage  (Reflection is slower than normal method calls)
         - Auto-configuration

12. Spring Startup Flow:
      Application Starts
               ↓
      Spring scans all classes
               ↓
      Finds annotations:
         - @Component
         - @Service etc
               ↓
      Creates Beans
               ↓
      Injects dependencies
               ↓
      Creates proxies if needed
               ↓
      Application ready

13. Why Spring Needs Reflection:
      → Spring does not know classes beforehand
      → At runtime Spring dynamically:
         - Finds classes
         - Reads annotations
         - Creates objects
         - Calls constructors
         - Injects dependencies
      → Reflection enables this dynamic behavior

15. AOP Runtime Flow
      → Suppose we want to use function 'X' from a library and apply additional functionality around it.
      → Before executing function X:
         - We can execute some methods
      → After executing function X:
         - We can execute some other methods

      → This before-and-after functionality is handled using AOP (Aspect-Oriented Programming)
      → AOP works dynamically at runtime 

      → If function X throws an exception or fails during execution:
         → We can also define methods:
            - before exception handling
            - after exception handling

16. Simple Real-Life Analogy of AOP
      Imagine:
         You enter mall
      Before entering:
         - Security check
         - Ticket validation
      Same in AOP:
         Extra logic runs:
         - before method
         - after method
         - around method

17.. Terminologies
      A. Join Point
         → Point where extra logic can be applied

      B. Advice
         → Actual action performed by aspect
         Types:
             - Before
             - After
             - Around
             - AfterReturning
             - AfterThrowing

      C. Pointcut
         → Defines WHERE aspect should apply

      D. Weaving
         → Process of connecting aspect with target object
