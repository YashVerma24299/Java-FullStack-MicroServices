1. What is Distributed System?
    → multiple machines/servers working together as one system
    → Why Distributed Systems Needed:
        - Single server problem:
            - limited traffic handling
            - server crash issue
            - scalability problem
        - Solution:
            use multiple servers together

    → Example:
        - 1 server handles: 1000 users
        - But: website has -> 10 lakh users
        - Then: one server NOT enough 
        - So company uses: many servers

2. What is Load Balancer?
    → Load Balancer distributes traffic across multiple servers
    → Without Load Balancer:
        All requests
            ↓
        One server
    → With Load Balancer:
        Users
            ↓
        Load Balancer
        ↙   ↓   ↘
        S1   S2   S3

3. Types of Load Balancing
    A. Round Robin
        Requests distributed one-by-one
        Example:
            Req1 → S1
            Req2 → S2
            Req3 → S3

    B. Least Connections
        Sends request to server having least active users

    C. IP Hash
        Same user routed to same server

4. (SQL(Backfilling) / NOSQL):
    - SQL databases are generally known for strong consistency and support ACID properties.

    - In SQL databases, we use tables to store data. Suppose a table already contains 10,000 records, and later we add a new column to that table.

    - For all newly inserted records, values for the new column can be provided normally. However, for the existing 10,000 records, the value of the newly added column will initially be `NULL`.

    - If we want to populate those existing `NULL` values with a specific default value, we generally use a process called **backfilling**. 
    - Backfilling means updating old records so that they contain meaningful data for the newly added column.

    - In NoSQL databases, data is usually stored in a more flexible structure, often similar to key-value pairs or JSON-like objects/documents. 
    - One advantage is that different objects/documents can have different fields. 
    - For example, if we add a new key to only the latest object, older objects are not affected, and there is no issue even if they do not contain that key.

    - Some popular NoSQL databases are: Apache Cassandra, ScyllaDB
    
    - This flexibility is one of the major differences between SQL and NoSQL databases.

    - Another important way to understand the difference between SQL and NoSQL systems is through the *CAP Theorem*:
        - Consistency (C) → Every server should show the same latest data.
        - Availability (A) → The system should always respond to requests, even if the data may not be fully updated.
        - Partition Tolerance (P) → The system should continue working even if communication between servers is interrupted due to network failures.

5. Consistency: Consistency in distributed systems and databases.
    - Suppose we have a cluster containing two database servers: DB1 and DB2.
    - A load balancer is placed in front of them, and whenever a request comes, the load balancer decides which database server should handle that request.

    - Now imagine a transaction request goes to DB1, and DB1 updates the data in memory,
    - for example adding ₹100 to an account balance.

    - If the same updated data is not reflected in DB2, then the databases become inconsistent.-
    - To maintain Consistency, the update made in DB1 must also be replicated to DB2 so that both servers contain the same data.

    - In simple terms, consistency means: Whenever data is updated on one server, the same updated data should be reflected across all servers in the cluster.
    - This is extremely important in distributed systems because requests can be routed to any server by the load balancer.

    - The same concept applies to authentication systems using refresh tokens.
        - Suppose a refresh token gets revoked or deleted on one server.
        - Later, when the user logs in again, the load balancer may route the request to another server.
        - If the token revocation was not synchronized across all servers, another server may still consider that refresh token valid.
