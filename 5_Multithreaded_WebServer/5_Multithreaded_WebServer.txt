1. What is a Server
    A server is simply a machine (computer or program) that provides services or data to other machines.
    A server = something that responds to requests
    Example:
    → You open a website → your browser sends a request
    → The server receives it → sends back data (HTML, JSON, etc.)

2. What is a Web Server
    A web server is a special type of server -> that handles HTTP/HTTPS requests.
    A web server = server that serves websites

3. Types of Servers:
    Web Server → serves websites
    Database Server → stores data
    File Server → stores files
    Application Server → runs business logic

4. Concept:
    When you use Spring Boot, it runs an embedded web server (like Tomcat)
    That’s why your app can handle requests like:  http://localhost:8080/.....

12. Client Server Flow
    1. User enters URL:
        Example: google.com

    2. DNS Lookup:
        System asks DNS:
            "What is IP of google.com?"
        DNS returns:
            142.250.xxx.xxx

    3. Request goes via ISP:
        ISP = Internet Service Provider (Jio, Airtel)
        Your request enters the internet through ISP

    4. Routers Forward Request:
        Routers find best path (like Google Maps)
        They forward request step by step to server

    5. Request reaches Server:
        Format: IP + Port
        Example: 142.250.xxx.xxx:443
        IP   = which machine
        Port = which service

    6. TCP Handshake (Connection Setup):
        Client → SYN
        Server → SYN-ACK
        Client → ACK -------then-------Connection established

    7. Server Processes Request:
        - Runs backend code
        - Fetches data from DB
        - Prepares response

    8. Response Sent Back:
        Client receives:
        - HTML (website)
        - JSON (API)

13. what is SOCKET
    -> Basic Definition: Socket = IP + Port
    -> It represents a connection endpoint
    
    -> But what does that REALLY mean?
        When 2 machines communicate:
            → One is client
            → One is server
        They don’t just use IP — they also need port to identify the exact service.
        So:
            → Socket = (IP address, Port number)

    -> Socket is created when: Client connects to server

    -> Real Example: 
        Client: 192.168.1.10:5000
        Server: 142.250.xxx.xxx:443
        This creates a connection: (Client IP + Port) ↔ (Server IP + Port)

    -> One server → many sockets

16. Context Switching
    -> CPU switching from one task/process/thread to another
    -> How Context Switching Works:
        Process A running
                ↓
        CPU saves state of A                                  
                ↓
        CPU loads state of B
                ↓
        Process B starts running

    -> IMPORTANT:
        PROBLEM:
            — Too many threads = too much switching
            — System slow ho sakta hai
        SOLUTION:
            — Thread pools
            — Async programming  -> JavaScript vaala Logic...
    
    -> More context switching ≠ more performance
    -> Excess switching actually reduces performance

    -> How CPU handles 2 threads at a single time:
        1. Normal:
            — Only one thread runs at a time.
            — But it switches very fast:
            — T1 → T2 → T1 → T2 → T1 ...
            👉 Each thread gets a small time slice

        2. Priority (VERY IMPORTANT):
            — T1 priority > T2 priority
            👉 Then:
                — T1 runs more
                — T2 gets less CPU
        
        3. Thread State
            — If a thread is: Waiting (I/O, API call, DB)
            👉 CPU gives time to other thread

        4. OS Scheduling Algorithm
            Round Robin
            Priority Scheduling
            Multilevel Queue

    -> Example Scenario:
        T1 = API request (waiting for DB)
        T2 = simple calculation
        Flow:
            T1 starts → waits for DB
            CPU switches to T2
            T2 runs fully
            T1 resumes later

18. Thread Pool:
    -> A thread pool is a group of pre-created threads that are reused to perform tasks.
    -> Instead of creating a new thread every time, we use existing threads from the pool
    -> Why needed:
        - Creating threads is expensive (takes time & memory)
    -> How it works:
        - Tasks (requests) come in
        - Thread pool assigns a free thread
        - Thread completes task
        - Thread goes back to pool (reuse)

    -> Example:
        100 users hit API
        → Instead of creating 100 threads
        → Use 10 threads in pool
        → Tasks handled one by one
